## Findings

### Blocking

- **B1 — Transitive alias merging conflates distinct models and revisions**
  - Location: `src/kforge/builder/graph.py:122-157`. The docstring claim is at
    `:123-125`; `README.md:273-275` makes the same claim.
  - Mechanism: union-find merges any alias that exactly one *name key* claims.
    There is no check that a name key links only one other group, so a short or
    ambiguous **name** (rather than alias) bridges distinct entities.
  - Reproduced with `merge_entities`, and end to end through P4 import and
    `consolidate`:
    - Two jobs each extract `3080`, one with alias `RTX 3080` and one with alias
      `RTX 3080 Ti`. Result: **one node** labeled `3080`, with aliases
      `RTX 3080` and `RTX 3080 Ti`.
    - Alias chain `RTX 3080` → `3080` → `RTX 3080 Ti`: the same single node.
    - Board `PG132` with alias `PG132 rev 1.0` in one job and alias
      `PG132 rev 1.1` in another: one node merging both revisions.
    - End to end: claims about the 3080 and the Ti share an entity node.
  - Impact:
    - It violates "merge equivalent entity aliases" and the plan's
      model/revision disambiguation.
    - The README sentence "`3080` cannot merge `RTX 3080` with `RTX 3080 Ti`"
      is false.
    - P6 knowledge packs would attach Ti claims to the 3080 entity (and
      rev 1.1 claims to rev 1.0).
  - Required fix: build the alias edges between name keys first, and merge an
    edge only when both ends have exactly one distinct neighbour group. That
    rules out a name key that links to two different groups, and chains
    through such a key. Alternatively, refuse any component whose merge would
    include two keys that are each a name and that are not linked by a mutual
    alias. Correct the docstring and README to match.
  - Verify: add the three scenarios above to
    `test_alias_merge_keeps_models_revisions_and_types_apart`, expecting
    separate nodes. The existing assertions (`RTX3080`/`rtx  3080`/
    `Ampere 3080` merge) must still pass.
- **B2 — Casefold merges SI unit prefixes, changing measurement values**
  - Location: `graph.py:69-70` (`_norm` uses `casefold`) and `:136`.
  - Reproduced: measurement entities `10 mΩ` and `10 MΩ` merge into one node
    labeled `10 MΩ`. `100 mV` and `100 MV` also merge. End to end, the claim
    "shunt reads 10 mΩ" and the claim "insulation reads 10 MΩ" share that node.
  - Impact: the graph links a milliohm claim to a megaohm entity, a factor of
    10⁹. The shipped `domain.example.yaml` has a `measurement` type, and its
    guidance insists on stated units. This conflicts with the invariants that
    measurement values are not invented and that source identities and
    metadata survive every transformation.
  - Required fix: do not casefold merge keys. Use NFKC plus whitespace collapse,
    so case variants merge only through an explicit alias. Alternatively, keep
    casefold but never for unit- or measurement-bearing types (e.g. a
    case-sensitive set in the domain config). Update README and `GRAPH.md`.
  - Verify: a test that `10 mΩ` and `10 MΩ` (and `mV`/`MV`) stay separate. If
    casefold is removed, adjust the `rtx  3080` expectation deliberately, for
    example by adding an alias.

### Non-blocking

  - Location: `graph.py:47` and `:113-115`.

    unrelated.") was accepted, and the claim became `contradicted`.
  - Impact: a single-character or partial-word quote proves nothing about the
    stance.
  - Fix: require a minimum quote length (e.g. ≥ 3 words or ≥ 15 non-space
    characters).
  - Verify: add a subtest.
- **N2 — `text_file` may point at a bundle file**
  - Location: `graph.py:73-84`.
  - Reproduced: `text_file: "a2.json"` (the bundle itself) made an arbitrary
    quote "found", and the claim became `corroborated`.
  - Fix: reject text files that are top-level `*.json` bundles (or require
    texts in a subfolder), and document it.
  - Verify: add a subtest.
- **N3 — A NUL byte in `text_file` aborts the whole consolidation**
  - Location: `graph.py:73-77` and `:248-249`.
  - Reproduced: `read_bundle` raised `ValueError: lstat: embedded null
    character in path`. In `consolidate`, that means the CLI exits 1 and no
    graph is written, even for valid bundles.
  - Fix: forbid NUL via the field pattern, or catch `ValueError`/`OSError` in
    `_text` and return an error.
  - Verify: a subtest that expects that bundle `rejected` and the others
    applied.
- **N4 — Dedup drops some provenance**
  - Location: `graph.py:263`, `:277-279`, `:298` and `:307`.
  - Issues:

    - Retrieval metadata appears only inside `evidence.jsonl`, so a document
      that no evidence uses has no retrieval record in any output.
  - Fix: keep the title per retrieval, add `bundles` to conflict records, and
    keep retrievals on document nodes (or in a documents file).
- **N5 — Entity node IDs can change as data grows**
  - The ID hashes the smallest merged key, so it changes when a new result
    joins a component with a smaller key. This is documented in `GRAPH.md`.
  - Impact: P6 paths and links derived from entity IDs may churn between
    builds. Consider this in P6.
- **N6 — Evidence precision**
  - Location: `docs/test-reports/P5.md:54`.
  - The report says `"verified"` "occurs in no output file", but the test checks
    only `claims`, `nodes` and `evidence`. My run checked all six files and
    found none, so the claim holds for the tested data; the wording overstates
    the test.
  - Update the README/docstring sentence as part of B1.

- **N9 — A single entity can still assert a wrong equivalence, and `GRAPH.md`

  - Location: `GRAPH.md:31-33` ("A bridge such as `3080` -> `RTX 3080` /

  - Observed: probe S1 and `repro_p5.py` show that one entity listing both
    models as aliases does merge the named `RTX 3080` and `RTX 3080 Ti`.
  - Why not blocking: this is an explicit agent assertion, not cross-job
    inference. Structurally it is identical to the benign multi-alias case the
    tests deliberately merge (`test_graph.py:105-107`), so no name-only rule can
    separate the two without also splitting benign entities. My own round-2
    prototype had this property and I did not flag it then. My round-1 B1
    end-to-end evidence used this single-entity form, so that particular
    reproduction remains. The cross-job form is fixed.
  - Fix:
    - Correct `GRAPH.md` to say that names listed together by one entity are
      treated as asserted equivalent and merge.
    - Record the limitation in HANDOFF.
    - Optionally add an alias definition at the next intentional
      `RESULT_SCHEMA_VERSION` bump ("other names of exactly this entity; never a
      different model, revision or variant"). Changing TASK.md or domain
      guidance now would invalidate every current job ID.
- **N10 — Merge cost is quadratic in an entity's alias count**
  - Location: `graph.py:143-144`.

    with more than 32 aliases as non-merging and map it by name), or document
    the limit.
