## Findings

1. **Blocking, medium — transcript verification inherited from video input**
   (`src/kforge/ingest/transcripts.py:195-204`). `asdict(video)` supplies
   `verification_status`, and new caption records never replace it. A constructed
   valid Manifest with `replace(video, verification_status='verified')` produces
   a successful canonical transcript marked `verified`, even though this phase
   performs no caption truth verification. The normal P1 discovery path defaults
   to unverified, but the public Python service also accepts constructed Manifest
   values. This violates the technical invariant and the documented transcript
   contract. Required fix: explicitly mark newly ingested caption records
   unverified; preserve the original source status in the retained manifest or
   separate discovery evidence. Add and run a deterministic regression with a
   preverified Video. Reviewer reproduction used `PYTHONPATH=tests .venv/bin/python`
   with the existing original synthetic fixtures; observed `status: succeeded`,
   `caption record verification_status: verified`, `confidence: unknown`.
2. **Nonblocking, low — lock identity depends on the supplied database pathname**
   (`src/kforge/ingest/transcripts.py:43-49`). A second process using a symlink
   alias to the same SQLite file acquires a separate sidecar lock. Existing docs
   require stable local paths, so this is a usage limitation within the P2
   contract rather than an acceptance blocker. Clarify that every worker must
   use the same database pathname and must avoid alias/hardlink paths, or
   canonicalize/reject aliases with appropriate tests if supporting them.
   Same-path subprocess contention was denied correctly; alias contention
   printed `acquired`; the original path acquired correctly after lock release.
