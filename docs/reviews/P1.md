## Findings

1. **Initially blocking; resolved — lost timestamp provenance**,
   `src/kforge/ingest/discovery.py:48` in the initial diff.
   `_metadata` only retains listed string fields and duration; it silently discards
   `timestamp`, `release_timestamp`, `modified_timestamp` and `release_date`.
   The locally installed yt-dlp YouTube tab extractor emits timestamp and scheduled
   release timestamp fields, and single-video metadata can contain exact temporal
   provenance. This conflicts with AGENTS.md: source timestamps must survive every
   transformation. A synthetic entry with these four fields is returned as status
   `ok`, but its summary and observation contain only its title.
   **Required fix:** retain supported temporal fields with JSON-safe numeric/string
   validation in both summary and every observation. Add offline regressions for
   temporal fields, conflicting duplicate values and invalid/nonfinite values;
   rebuild/reinstall, rerun affected/full tests and request an updated diff review.
2. **Initially advisory; resolved — malformed numeric metadata aborts a collection**,
   `src/kforge/ingest/discovery.py:57` in the initial diff. `math.isfinite(10**1000)` raises
   `OverflowError`; a valid-ID entry with this synthetic duration causes
   `backend_error`, prevents that video from being recorded and discards subsequent
   valid collection entries. Legitimate durations are small, so this does not block
   normal P1 discovery. **Recommended fix:** safely reject unrepresentable optional
   numeric fields and continue discovery; add a regression proving the subsequent
   entry survives. Apply the same handling to numeric timestamps added for finding 1.
