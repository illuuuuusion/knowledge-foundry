## Review round 1 and fixes

The separate reviewer (docs/reviews/P5.md) requested changes: **B1** alias links
could bridge distinct models/revisions (`3080` aliasing both `RTX 3080` and
`RTX 3080 Ti`, alias chains, `PG132` aliasing two revisions); **B2** casefolded
matching merged `10 mΩ`/`10 MΩ` and `100 mV`/`100 MV`. Non-blocking N1–N6:
one-character quotes, a bundle file as its own text, NUL path aborting the run,
dedup losing titles/conflict bundles/unused document metadata, node ID churn,
and test-report wording.

Fixes: case-sensitive NFKC/whitespace matching; different names merge only when
every pair among them is alias-linked (complete link graph); labels use the most
frequent normalized name. Quotes need >= 10 characters; documents must be used by
evidence; top-level bundle `.json` files cannot be text files; OS/NUL path errors
reject only that bundle; retrievals keep their titles; conflict edges list their
bundles; every output file is checked for `"verified"`. N5 is documented.

Tests: the alias test was replaced by direct `merge_entities` scenarios (the three
reviewer reproductions, unit prefixes, Ohm sign NFKC, case/type separation, a
complete triangle and a pair that do merge) plus an end-to-end claim mapping test;
four invalid-bundle subtests added (short quote, unused document, bundle as text,
NUL path). The first rerun used the stale installed package (tests import the
installed kforge): 5 failures, 3 errors. It also exposed a real tie-break issue
(label `RTX  3080` with a double space), fixed by normalized labels. After
reinstalling, one failure remained: a wrong expected sort order in the new test,
corrected in the test. Final:
`.venv/bin/python -m pip install --no-build-isolation --no-deps --no-cache-dir -q .`
and `.venv/bin/python -m unittest discover -s tests -q`: **163 tests passed**,
no failures/errors/skips, exit 0. A scratch spy printed the intended rejection
reason for each new invalid case. Installed-source parity: 21 files.

## Review round 2 and fixes

The follow-up review confirmed B1/B2/N1–N6 for the reported scenarios and found
**B3**: `RTX 3080`, plus `3080` aliased `RTX 3080` in one job and `3080` aliased
`RTX 3080 Ti` in another, merged the Ti entity into the RTX 3080 node, because
equal names always merge and alias-only strings were ignored by the completeness
check. Non-blocking: N7 case-insensitive filesystems let `A2B.JSON` read a bundle;
N8 RESEARCH.md did not state the new bundle rules.

Fixes: every entity links its name and aliases pairwise; union-find groups all
strings (alias-only strings included); a group merges its names only if it is a
complete graph (link count per group, O(links)). The text-file suffix check is
case-insensitive. RESEARCH.md now states the subfolder rule, the 10-character
quote minimum and that every document must be cited. README/GRAPH.md/docstring
sentences that overclaimed were corrected and the equal-name limitation documented.

Tests: B3 direct scenario, a benign star with extra aliases that merges, an
end-to-end test that the Ti claim never shares an entity with the RTX 3080 claim,
and an upper-case bundle-as-text subtest. A scratch check loaded the previously
staged graph.py: on the B3 scenario it produced 1 node (job 0 and job 2 merged);
the new code produces 2 nodes and keeps them apart. A first attempt to apply the
fix aborted on a docstring mismatch before writing anything; a full suite run at
that moment (163 passed) still reflected the old code and is not counted.
After applying and reinstalling: `.venv/bin/python -m unittest discover -s tests -q`
**164 tests passed**, no failures/errors/skips, exit 0.
