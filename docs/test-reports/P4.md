## Omissions and residual limits

- Model invocation is outside the deterministic suite (per plan). The separate
  reviewer performed a code-blind job-agent smoke (it had not read the code, but was told the input contained an injection and was given the import command, directory and domain path); see Review follow-up below.
- No live YouTube, Python 3.11, minimum pydantic/PyYAML versions or remote CI.
  CI installs the package and therefore the new core dependencies.
- Pydantic's JSON parser accepts duplicate object keys (last value wins); the
  stored result is the normalized model dump, so stored data is unambiguous.
- Citation check is span + overlap against the job's segments, not exact segment
  boundary matching; a citation may cover a gap if it also overlaps a segment.
- A citation touching a segment edge may extend into the following gap (review N2).
- Deleting an imported result.json reports `pending`; stale folders exit 0 (N7).
- Import reads all stored transcripts to recompute expected jobs (local MVP scale).
- Results imported under older domain settings remain in SQLite keyed by job ID;
  P5 must select current jobs or domains explicitly.
- `export` and `jobs` on a v2 store require `kforge init` (or any scrape) first.
